# Wiki conventions

The rules every wiki reader and writer follows. Other skills cite sections of this file by name
(`skills/pavilio-wiki/CONVENTIONS.md § Reading ladder`); keep the headings stable.

## Layout

```
projects/<p>/
├── CONTEXT.md                 # strict glossary: one line per term + See [[wiki/concepts/<term>]]
└── wiki/
    ├── .gitignore             # .ingest.lock, raw/repos/
    ├── log.md                 # append-only: ingest/query entries + the ledger
    ├── .ingest.lock           # transient, never committed
    ├── raw/                   # raw layer: verbatim snapshots of outside material
    │   └── repos/<owner>-<repo>/   # shallow clones, never committed
    ├── index.md               # GENERATED — sections only, one line each
    ├── overview.md
    ├── sources/               # one source page per record: <kind>-<stem>.md
    ├── entities/              # kind: person | repository | service | organization
    ├── concepts/              # domain knowledge; never names files or functions
    ├── repos/<repo>/          # code subtree: ARCHITECTURE.md + code-level notes
    ├── questions/             # one page per explicit query
    ├── notes/                 # synthesised answers worth keeping
    └── open-questions.md      # ## Gaps, ## Knowledge candidates
```

Every `index.md` (root, each section, each `repos/<repo>/`) is generated by `scripts/wiki index`.
Never edit one by hand; regenerate it.

## Identity and the ledger

- **Record** — a closed workspace file: `notes/**`, `memo/**`, past-day `progress/*.md`, `adr/**`,
  an archived change's `proposal.md` / `design.md`. Never `tasks.md`, delta specs, or today's
  progress. Records are cited in place by their project-relative path, never copied.
- **Raw file** — anything without a stable workspace home, snapshotted verbatim under `wiki/raw/`:
  `<slug>.md` (outside file), `article-<slug>.md`, `snippet-<YYYY-MM-DD>-<slug>.md`,
  `context-snapshot-<YYYY-MM-DD>.md`, its per-section split
  `context-snapshot-<YYYY-MM-DD>/<nn>-<section-slug>.md` (written by migrate; source page
  `sources/context-snapshot-<YYYY-MM-DD>-<section-slug>.md`), `repos/<owner>-<repo>/`. A raw file
  is never rewritten (clones are refreshed in place by `clone-repo`).
- **Source page** — `wiki/sources/<kind>-<stem>.md`, one per record or raw file. `<kind>` is
  `note`, `memo`, `progress`, `adr`, `proposal`, `design`, `file`, `article`, `snippet` or
  `context`; `<stem>` is the file stem with a leading `<kind>-` stripped (the change id for
  `proposal`/`design`), so raw `article-edge-tts.md` → `sources/article-edge-tts.md`, never
  `article-article-…`. On a stem collision append the parent directory name. A changed record rewrites its existing source page.
- **Slug** — lowercase kebab-case ASCII; people `first-last`. Frontmatter lists carry bare names
  (`concepts: [utterance]`); receipts, `mentions --touched` and page writers use the namespaced
  form `entities/<name>` / `concepts/<name>`, whose page is `wiki/<slug>.md`. Reuse an existing
  slug or alias before coining one.
- **Ledger** — `- ingested: <project-relative path> #<sha256 first 12 hex>` lines in `wiki/log.md`,
  appended only by `scripts/wiki record`, and only after the record's source page landed. A path
  whose latest hash matches is done; a different hash is `changed`; no line is pending. Repo clones
  are tracked by `commit` in their repo pages, not by the ledger.
- **Lock** — `wiki/.ingest.lock` (`{session, ts}`) via `scripts/wiki lock`; one ingest per wiki;
  older than 15 min is taken over.

## Two sources, and the glossary exemption

A knowledge page (`entities/`, `concepts/`) is written only when ≥2 distinct source-like pages
name its slug. Source-like = `sources/**` and `repos/<repo>/**`; `questions/` and `notes/` never
count. A term `CONTEXT.md` links as `See [[wiki/concepts/<slug>]]` qualifies with one source.
`scripts/wiki mentions` decides; never write a knowledge page it did not list as `qualifying`.

## Write regimes

| Path | Writer | Regime |
|---|---|---|
| `raw/` | ingest routing, `fetch-article`, `clone-repo` | written once; clones refreshed |
| `sources/` | `source_writer` | one per record; rewritten when its hash changes |
| `entities/`, `concepts/` | `page_writer` | incremental rewrite from the existing page + new source pages only |
| `repos/<repo>/` | `repo_writer` | `ARCHITECTURE.md` rewritten on clone refresh; notes added |
| `overview.md` | `overview_writer` | rewritten when knowledge pages change |
| `index.md` files | `scripts/wiki index` | generated |
| `questions/` | query | one new page per explicit query; never edited after |
| `notes/` | query | new, or enriched in place |
| `open-questions.md` | query, ingest | append items; people resolve and delete them |
| `log.md` | query, ingest, `scripts/wiki record` | append-only |
| `CONTEXT.md` | archive-plan, migrate | never this skill |

People may edit any page. Writers keep `created` and human-added `aliases`.

## Links

One syntax (D14): `[[<path from project root>]]`, no `.md`, optional `<project>:` prefix and
`|label` suffix.

- `[[wiki/concepts/utterance]]`, `[[wiki/entities/jane-doe|Jane]]`
- `[[progress/2026-10-19-tts-relay-node20]]`, `[[adr/0020-agent-memory-is-an-llm-wiki-context-is-a-glossary]]`
- `[[plans/openspec/specs/speech/spec]]`
- `[[metro:wiki/entities/jane-doe]]` — another project

Never relative paths (`../`), never markdown links to workspace files, never a bare slug
(`[[utterance]]`). Every claim on a knowledge page cites the source page it came from.

Frontmatter paths: `sources:` and `cited:` entries are project-root paths with `.md`
(`wiki/sources/<kind>-<stem>.md`) so lint resolves them; `record:` and `raw:` are project-relative
paths with `.md`. A YAML list item that starts with `[[` must be quoted (`- "[[wiki/…]]"`).

## No code identifiers outside `repos/`

`entities/` and `concepts/` describe the domain: what a thing is, why it is so, what broke and why,
who decided. They never name files, paths, functions, classes, components, flags or env vars. Where
a concept is implemented, link the repo page: `see [[wiki/repos/pavilio/speech-relay]]`. Code-level
detail lives only under `wiki/repos/<repo>/`. `scripts/wiki lint` flags violations as
`codeIdentifiers`.

## Reading ladder

The reading ladder is the fixed read order for any skill or query that needs project knowledge.
It is the budget, not a minimum — stop as soon as the question is answered.

1. `CONTEXT.md` — the glossary, always, whole.
2. `wiki/index.md` — sections only.
3. ≤2 section indexes, chosen by their one-line descriptions.
4. ≤3 pages, chosen by their index descriptions: knowledge pages before source pages. Open a
   record only when a source page points at it and the pages did not answer.
5. `wiki/repos/<repo>/` only when the question or task is about code — descend from the
   repository entity page (`repos/<repo>/index.md`, then ≤2 repo pages). Never for a general
   question.
6. A `<project>:` link to another project's wiki only when the page in hand does not answer.

No `wiki/` → read `CONTEXT.md` whole, as before. Readers other than `/pavilio-wiki` queries walk
the ladder without logging or writing anything.
